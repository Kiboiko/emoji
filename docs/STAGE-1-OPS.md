## Установка

Linux с systemd, Python 3 (stdlib), Bash, flock, gzip, sha256sum и Docker Compose v2. Запускаются от root: доступ к Docker эквивалентен root. Сначала сверить файлы с другим разработчиком, сохранить заменяемые файлы и существующую конфигурацию. Не копировать локальный Compose/override на сервер.

После копирования `scripts/backup-db.sh`, `scripts/ops.py`, `scripts/install-ops.sh` в существующий каталог проекта:

```bash
cd /opt/marketplace
chmod 600 .env
python3 scripts/ops.py test-notification
python3 scripts/ops.py backup
sudo bash scripts/install-ops.sh
systemctl status gram-market-backup.service gram-market-monitor.service
journalctl -u gram-market-backup.service -u gram-market-monitor.service --since today
```

Установка повторяемая: заменяет только четыре `gram-market-{backup,monitor}.{service,timer}`. Удалить старое cron-задание бэкапа, если оно было, чтобы не было двойного расписания. Дамп — в 03:30 Europe/Moscow (даже если сервер работает в UTC); пропущенный запуск выполняется после включения (`Persistent=true`). Монитор — раз в минуту после двух минут загрузки. Проверить `systemctl list-timers 'gram-market-*'` и часовой пояс сервера. Для немедленной проверки: `systemctl start gram-market-monitor.service`.

`TELEGRAM_BOT_TOKEN` и список `ADMIN_CHAT_ID` через запятую читаются из существующей `.env` без выполнения shell. При совпадении ключа значение `.env` имеет приоритет над окружением процесса, включая дочерний backup. Значения должны быть простыми строками, без интерполяции `${...}`. Токен не передаётся аргументами процесса и не печатается. В Telegram уходят только фиксированные названия неисправностей, без строк журналов, URL, персональных данных и секретов. Каждый администратор должен иметь возможность получать сообщения от бота.

Дополнительные ключи `.env` (необязательные):

- `OPS_SERVICES=postgres backend bot nginx frontend admin` — ожидаемые постоянно работающие сервисы; адаптировать, если серверный Compose отличается.
- `OPS_PUBLIC_HEALTH_URL=https://example.org/api/categories` — дополнительная HTTP-проверка публичного адреса, без авторизации; по умолчанию используется `SITE_URL` + `/health`, если `SITE_URL` задан. Внутренний backend `/health` проверяется всегда через контейнер.
- `OPS_STATE_DIR=/var/lib/gram-market-ops` — каталог состояния, права 700; не очищать при каждой выкатке.
- `BACKUP_DIR=/opt/marketplace/backups`, `KEEP_DAYS=14` — параметры дампа. В `.env` эти два параметра читаются обёрткой `ops.py`; при прямом запуске Bash передавать их переменными окружения.

Сбой контейнера, Docker, backend health, чтения логов, новые `ERROR`/`Traceback` backend/bot и отсутствие успешного дампа за 26 часов дают уведомления. Неизменный сбой не повторяется; восстановление уведомляется отдельно. Ошибки приложения закрываются после пяти минут тишины. Первый запуск смотрит последнюю минуту, последующие — с сохранённой временной отметки; чтение ограничено 2000 строк на сервис, поэтому это оперативный сигнал, а не полный аудит. При большом потоке логов возможна потеря ранних ошибок между проверками. Недоставленные уведомления повторяются; при нескольких чатах частичная доставка может повториться в уже успешные чаты. Отсутствие Telegram/самого сервера нельзя сообщить с этого же сервера: для этого нужен внешний uptime/heartbeat монитор.

## Дамп и восстановление

Дамп пишется в `.part`, при любой ошибке удаляется временный файл. Bash `pipefail` проверяет и `pg_dump`, и gzip; `gzip -t` проверяет сжатый поток. После успеха создаются SHA256 и `.last-success`, затем удаляются только дампы этой базы старше 14 суток. До успеха нового дампа ротация не запускается; страховочные `pre-restore_*` не затрагиваются. `flock` исключает параллельные дампы, `umask 077` закрывает доступ другим пользователям. Прямой запуск: `bash scripts/backup-db.sh` (всегда явный основной Compose).

`gzip -t` и SHA256 не доказывают возможность восстановления. Обязательная проверка на отдельной временной БД:

```bash
cd /opt/marketplace
gzip -t backups/ИМЯ_ДАМПА.sql.gz
sha256sum -c backups/ИМЯ_ДАМПА.sql.gz.sha256
TARGET_DB=marketplace_restore_test bash scripts/restore-db.sh backups/ИМЯ_ДАМПА.sql.gz
```

Вручную проверить `TARGET_DB` перед вводом `yes`: скрипт удаляет и создаёт эту базу, не использовать рабочую или чужую тестовую базу. Проверить таблицы, числа пользователей/заказов/сделок/проводок, Alembic revision; результат записать в акт выкатки. Проверять восстановление регулярно и после изменения схемы. Отдельная копия вне сервера ещё требует согласованного защищённого хранилища; локальный дамп не защищает от потери сервера. Скрипт restore не запускается таймерами.

Отключение: `systemctl disable --now gram-market-backup.timer gram-market-monitor.timer`. Это сохраняет дампы и состояние, сервисы при необходимости остановить отдельно. Код/БД этими операциями не откатываются.
