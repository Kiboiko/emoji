# Чек-лист выкатки на боевой сервер

Пройти целиком перед первым запуском в продакшене. Пункты со знаком **!**
означают деньги или доступ: пропуск любого из них — реальный ущерб, а не
неудобство.

---

## 1. Секреты

**!** Все секреты из архива предыдущего разработчика считать
**скомпрометированными**: они лежали в репозитории. Владелец площадки должен
выпустить заново:

- [ ] `TELEGRAM_BOT_TOKEN` — перевыпустить у @BotFather (`/revoke`)
- [ ] `SECRET_KEY` — новый случайный (`openssl rand -hex 32`)
- [ ] `DB_PASSWORD` — новый
- [ ] `ADMIN_PASSWORD` — новый, не совпадающий ни с чем
- [ ] `INTERNAL_API_TOKEN` — новый случайный
- [ ] `TON_API_KEY` — свой ключ toncenter
- [ ] Токен CryptoBot — **отозвать**, платёжка больше не используется

- [ ] `.env` не в git (`git check-ignore .env` должен его вернуть)
- [ ] Права на `.env` — `chmod 600`
- [ ] **!** Доступ разработчиков к серверу закрыт: пароль `root` сменён,
      из `~/.ssh/authorized_keys` (у `root` и у остальных пользователей)
      удалены ключи, которые вы не узнаёте

## 2. Переменные окружения

| Переменная | Локально сейчас | Должно быть в проде |
|---|---|---|
| `DEBUG` | `true` | **`false`** |
| `VITE_DEV_AUTH` | `true` | **`false`** |
| `COOKIE_SECURE` | `false` | **`true`** |
| `TON_NETWORK` | `testnet` | **`mainnet`** |
| `SITE_URL` | localhost | боевой домен с `https://` |
| `VITE_API_URL`, `CORS_ORIGINS` | localhost | тот же домен |
| `TON_RECEIVING_ADDRESS` | тестовый | **боевой кошелёк площадки** |
| `TON_API_KEY` | ключ testnet | **ключ toncenter для mainnet** (ключи у сетей разные) |
| `APP_NAME` | `Gram Market` | название, которое кошелёк покажет при подключении |
| `VITE_BOT_USERNAME` | тестовый бот | боевой бот, без `@` |
| `ADMIN_CHAT_ID` | — | чат(ы) администраторов через запятую |
| `REVIEWS_CHANNEL_ID` | пусто | канал для отзывов; пусто — отзывы в канал не публикуются |

`SITE_URL`, `APP_NAME`, `VITE_*` попадают в витрину **при сборке образа**: после
их смены нужна пересборка фронта (`docker compose -f docker-compose.yml build
frontend`), простого перезапуска мало.

**!** `DEBUG=true` в проде регистрирует `POST /api/auth/dev`, который выдаёт
админский токен **без пароля**. Именно так эта дыра и существовала в
доставшемся коде.

**!** `TON_NETWORK=testnet` на проде означает приём тестовых монет: покупатель
заплатит настоящими, а площадка будет искать перевод в другой сети.

- [ ] Проверено, что `docker-compose.override.yml` на сервере **отсутствует**.
      Он монтирует код внутрь контейнера, включает `--reload` и пробрасывает
      порт 8000 наружу. Запуск в проде: `docker compose -f docker-compose.yml up -d`
- [ ] `/api/internal/` не доступен снаружи (`curl https://домен/api/internal/relay`
      должен вернуть 404 — так настроен nginx)

## 3. Домен и HTTPS

- [ ] Домен указывает на сервер, сертификат выпущен

      nginx из docker-compose слушает HTTP на `HTTP_PORT` (по умолчанию 8080).
      HTTPS ставится перед ним на самом сервере: Caddy или внешний nginx с
      сертификатом Let's Encrypt, проксирующий на `127.0.0.1:8080`. На тестовом
      сервере так работает Caddy. Ограничение на размер запроса в нём не
      ставить ниже 25 МБ: фото в чат и в объявления до 20 МБ.

- [ ] Манифест TON Connect открывается: `https://домен/tonconnect-manifest.json`

      Манифест генерируется при сборке образа из `SITE_URL`. Кошелёк скачивает
      его сам и сверяет origin — **с localhost полный прогон оплаты
      невозможен**, нужен публичный HTTPS.

- [ ] В @BotFather у бота прописан правильный URL Mini App
- [ ] Кнопки Telegram со ссылками работают: при `http://` Telegram отклоняет
      сообщение целиком, а не только кнопку

## 4. База данных

- [ ] `alembic upgrade head` выполнен **до** старта приложения
- [ ] Перед миграцией снят дамп базы (`pg_dump`) и проверен (`gzip -t`). Миграции
      этапа 1 (`0024`–`0027`) только добавляют колонки, таблицы и индексы.
      `0027` создаёт триграммные индексы поиска и расширение `pg_trgm`; если
      расширения в базе нет, миграция предупреждает и продолжает без них,
      поиск тогда работает, но медленнее на большом каталоге
- [ ] Миграции **не запускаются сами** при старте контейнера, а бэкенд
      откажется стартовать на неактуальной схеме: после сборки образа выполнить
      `docker compose run --rm --entrypoint alembic backend upgrade head`,
      и только потом `up -d --force-recreate backend`
- [ ] `alembic check` — «No new upgrade operations detected»
- [ ] Приложение стартует (при расхождении схемы оно откажется — это норма)
- [ ] Бэкап настроен в cron и **проверен восстановлением** в отдельную базу
      (см. README, раздел «Бэкапы»). Непроверенный бэкап не считается.

## 5. Настройки площадки

Задаются в админке (раздел «Настройки»), не в `.env`. Проценты вводятся в
процентах, суммы — в Gram. Подробно — в `docs/ADMIN-GUIDE.md`.

| Настройка | По умолчанию | Проверить перед стартом |
|---|---|---|
| Сколько минут ждать оплату заказа (`order_payment_ttl_min`) | 3 | **!** Не больше нескольких минут. Всё это время (плюс минута запаса) товар забронирован и не виден в каталоге. На время тестов ставилось 720: счёт жил 12 часов, а курс за это время уходит далеко |
| Комиссия с продажи товара | 2% | Согласовать с владельцем |
| Комиссия с подписки | 2% | Согласовать |
| Реферальные, первый уровень | 3% | Согласовать |
| Реферальные, второй уровень | 0 (выключен) | Согласовать |
| Минимальная сумма вывода | 1 Gram | Согласовать |
| `ton_rate_source` | `coingecko` | Оставить. `fixed` — только на случай недоступности источника |
| Контакт поддержки | пусто | Указать @username или ссылку. Пусто — кнопка «Поддержка» ведёт в чат с ботом |
| Текст условий площадки | **пусто** | **!** Заполнить. Пока пусто, люди принимают пустой документ, и в споре сослаться не на что |
| Версия условий | 1.0 | Поднять при первом заполнении текста |
| Магазин площадки (Модерация → Магазин площадки) | — | Название, описание и логотип магазина, от имени которого продаются ваши товары |

## 7. Финальный прогон на боевой конфигурации

Пройти сценарии целиком, реальными деньгами на небольшую сумму:

- [ ] Покупка обычного товара: оплата → списание с кошелька → заказ оплачен →
      товар выдан
- [ ] Сверка балансов в админке говорит «сходится»
- [ ] Реферальное начисление появилось у пригласившего
- [ ] Подписка: оплата → приглашение → вход в канал
- [ ] Товар пользователя: заявка → модерация → покупка → **деньги заморожены,
      продавцу не начислены** → чат между сторонами работает → подтверждение →
      деньги у продавца за вычетом комиссии
- [ ] Спор: открыть и разрешить в обе стороны
- [ ] Возврат денег продавцом из чата сделки
- [ ] Заявка на вывод из профиля и выплата кнопкой «Выплатить» в админке:
      заявка закрылась сама, деньги пришли на кошелёк
- [ ] Отзыв после покупки появился у товара (и в канале, если он настроен)
- [ ] Блокировка пользователя действительно закрывает доступ

## 9. Обновление уже работающего сайта

Порядок для каждой следующей выкатки. База данных не должна пострадать ни при
каком обновлении, поэтому дамп первым, миграции отдельным шагом.

1. **Сверка с сервером.** Файлы на сервере могли править без вас: сравнить
   каталог `/opt/marketplace` с репозиторием (учесть окончания строк CRLF/LF)
   и не затирать чужие правки.
2. **Дамп базы:** `docker compose exec -T postgres pg_dump -U $DB_USER $DB_NAME | gzip > backup.sql.gz`,
   проверка `gzip -t backup.sql.gz`. Рядом сложить архив заменяемых файлов.
3. **Сборка и тесты** на временной базе (образ собирается, `pytest` проходит).
4. **Миграции отдельным шагом** (сами не запускаются):
   `docker compose run --rm --entrypoint alembic backend upgrade head`.
5. **Перезапуск:** `docker compose up -d --force-recreate backend frontend`.
   Админка собирается отдельно: `docker compose build admin && docker compose up -d --force-recreate admin`.
6. **nginx** перечитывает конфиг без остановки, но только после проверки:
   `docker compose exec nginx nginx -t && docker compose exec nginx nginx -s reload`.
   Если проверка не прошла, перезагрузку не делать: работает прежний конфиг.
7. **Проверка после выкатки:**
   - все контейнеры `healthy`, в логе `Схема БД актуальна`;
   - `curl -sI https://домен/api/categories` дважды подряд: во втором ответе
     заголовок `X-Cache-Status: HIT`;
   - `docker compose exec nginx nginx -T | grep -E "worker_rlimit_nofile|worker_connections"`:
     лимит файлов выше числа соединений (иначе под нагрузкой nginx отвечает 500
     «No file descriptors available»);
   - в логе бэкенда нет токена бота: `docker compose logs backend | grep -c "bot[0-9]*:AA"`
     должно быть 0 (вместо токена стоит `<скрыто>`);
   - вход в админку и открытие каталога с телефона.
8. **Откат.** Бэкенд сверяет версию схемы с кодом строго: старый код на базе с
   новыми миграциями **не запустится**. Поэтому порядок такой: сначала
   откатить миграции **новым** образом, пока он ещё собран
   (`docker compose run --rm --entrypoint alembic backend downgrade <ревизия до выкатки>`,
   для миграций `0026`/`0027` это `b3c4d5e6f7a8`; они удаляют только индексы,
   данные не трогают), затем вернуть файлы из архива, пересобрать и
   `up -d --force-recreate backend frontend`. Дамп из шага 2 — на крайний случай.

Публичные ответы каталога кешируются в nginx на 3 секунды. Правка в админке
видна покупателям не позже чем через ~4 секунды; сама админка кеш обходит
и видит свои правки сразу.

## Что осталось незакрытым на момент передачи

- **В сети mainnet ничего не прогонялось.** Проверка шла автотестами и на
  тестовом сервере с HTTPS-доменом в сети testnet. Первый прогон реальными
  деньгами — по разделу 7 после переключения на mainnet.
- **Текст условий площадки не предоставлен владельцем.** Механика работает,
  документ пустой.
- **Дамп боевой схемы БД не предоставлен.** Миграции проверены на локальной
  копии; на боевой базе первый `alembic upgrade head` нужно делать после
  бэкапа и читать вывод.
- **Языковые строки не вынесены в словари** (75 мест). Работа отложена
  сознательно: при выбранном варианте оформления она не даёт пользователю
  ничего, а риск задеть строки реальный.
- **Пароль администратора всё ещё из `.env`.** Роли разделены (администратор и
  модераторы со своими логинами), но пока владелец не сменил пароль в разделе
  «Безопасность», действует пароль из `.env`. После смены `.env` перестаёт
  открывать вход.
- **Автоматического ежедневного бэкапа базы нет.** Дамп перед каждой выкаткой
  снимается вручную. Ежедневный бэкап по cron с проверкой восстановления
  согласован как отдельная работа.
