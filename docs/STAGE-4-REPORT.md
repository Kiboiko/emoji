# Этап 4 — Подписки на закрытые каналы. Отчёт

Дата: 2026-09-14. Всё проверено на локальном стенде.

---

## Ограничения Telegram, определившие схему

Три пункта из `WORK_PLAN.md` (часть III) реализованы так, как позволяет Bot API, а не так, как было записано в ТЗ:

1. **Бот не может добавить пользователя в канал по `user_id`.** Метода `addChatMember` в Bot API нет — он существует только в клиентском MTProto. Доступ выдаётся **персональной одноразовой инвайт-ссылкой** (`createChatInviteLink` с `member_limit=1` и сроком жизни сутки), по которой человек входит сам.

2. **Отзыв доступа — это два вызова.** `banChatMember` затем `unbanChatMember` с `only_if_banned=True`. Один только ban оставляет человека в вечном бане, и он не сможет купить подписку повторно. `only_if_banned` не трогает тех, кого забанила администрация за нарушения.

3. **Апдейты `chat_member` Telegram по умолчанию не присылает.** Их нужно явно перечислять в `allowed_updates`. В боте это `dp.resolve_used_update_types()` — без него выдача доступа работала бы вслепую: нельзя отличить «купил, но не перешёл по ссылке» от «пользуется каналом».

**Настоящего автопродления в TON не существует** — каждая транзакция требует подписи в кошельке, рекуррентных списаний нет. Поэтому реализовано напоминание + кнопка «продлить», а флаг «автопродление» в интерфейсе намеренно не заводится, чтобы не вводить людей в заблуждение.

## Что сделано

### Модель данных

`channels`, `subscription_plans`, `subscriptions`, `subscription_access_log`. Существующие таблицы не тронуты.

**Подписка продаётся как обычный товар.** При создании тарифа автоматически заводится `Product` с `type='subscription'`, а id тарифа кладётся в `content_data`. Благодаря этому подписка проходит через ту же корзину, заказ и оплату, что и остальные товары — отдельный путь покупки ради подписок не нужен, существующий уже протестирован.

**Журнал доступа** (`subscription_access_log`) фиксирует каждую выдачу, вход, выход, кик и каждую ошибку Telegram. Без него на вопрос «почему у меня нет доступа» ответить нечем: причин отказа у Telegram много — бота разжаловали, канал удалён, пользователь заблокировал бота.

### Подключение канала автором

1. Автор указывает `@username` или `chat_id`, кошелёк для выплат, принимает условия площадки (версия фиксируется в БД).
2. Бэкенд сразу проверяет права бота: нужны `can_invite_users` и `can_restrict_members`.
3. Канал создаётся в любом случае — чтобы автор мог добавить бота и нажать «Проверить».
4. **Опубликовать канал без подтверждённых прав нельзя.** Иначе подписки продавались бы на канал, доступ в который выдать невозможно.
5. Права проверяются **повторно в момент одобрения модератором**: между подачей заявки и решением автор мог разжаловать бота.

### Выдача и отзыв доступа

После подтверждения оплаты `complete_order()` активирует подписку и отправляет ссылку отдельным сообщением — она одноразовая и с TTL, теряться среди прочих уведомлений о покупке не должна.

**Продление суммирует срок, а не перезаписывает.** Пользователь, купивший второй месяц до окончания первого, не теряет оплаченные дни. Если подписка уже истекла — срок считается от сегодня, а не «минус просроченное».

Ошибка Telegram при выдаче **не откатывает оплату**: подписка уже оплачена, падение выдачи фиксируется в журнале и админу уходит алерт для ручной выдачи.

Отзыв работает симметрично: если Telegram отказал (канал удалён, бота разжаловали), подписка всё равно закрывается — иначе висела бы активной вечно и блокировала повторную покупку.

### Сплит комиссии

Деньги уже на счёте платформы (их зачислил `payment_service` при подтверждении оплаты), поэтому сплит — внутренний перевод: комиссия остаётся платформе, остаток начисляется автору.

Доля позиции в заказе считается **от фактически поступившей суммы**, а не от цены в USD: курс на момент оплаты уже зафиксирован, пересчитывать его заново значило бы начислить автору не то, что реально пришло. Округление вниз оставляет копеечный остаток платформе — автору никогда не начислится больше, чем поступило.

Выплата автору наружу — **ручная**, через существующий механизм заявок на вывод. Автоперевод требовал бы приватного ключа горячего кошелька на сервере; для площадки, держащей чужие деньги, это лишний риск.

### Фоновые задачи

Джоба раз в час: закрывает истёкшие подписки с отзывом доступа и шлёт напоминания за 3 дня и за 1 день. `reminder_sent_for_days` не даёт слать одно и то же напоминание при каждом прогоне.

Раз в час, а не чаще: доступ в канал не требует посекундной точности, а каждый прогон — это вызовы Telegram API по каждой истёкшей подписке.

### Внутренний API для бота

Бот живёт отдельным контейнером, и апдейты `chat_member` получает только он. Добавлен `POST /api/internal/chat-member`, закрытый общим секретом `INTERNAL_API_TOKEN`.

Пустой секрет **не означает «пускать всех»** — эндпоинт отдаёт 503. В nginx путь `/api/internal/` наружу не проксируется.

### Интерфейсы

- **Витрина:** блок «Мои подписки» в профиле — статус, срок, дни до конца, кнопка входа в канал и перевыпуск ссылки, если не успел перейти. Каталог подписок работает сам: они лежат в общем списке товаров.
- **Админка (API):** очередь модерации каналов, одобрение/отклонение/снятие, список подписок с фильтрами, журнал доступа по подписке, ручной отзыв и ручная выдача ссылки. UI — этап 7.

## Что нужно от заказчика

1. **Бот должен быть администратором в канале каждого автора** с правами приглашать и ограничивать участников. Это надо прописать в условиях площадки — технически проверка уже стоит и без прав канал не опубликуется.
2. **Текст условий площадки.** Версионирование и фиксация согласий реализованы, сам текст нужен от вас.
3. **Тестовый канал** для сквозной проверки: создать закрытый канал, добавить туда бота админом, подключить через кабинет автора. Без реального канала проверить выдачу и отзыв доступа нельзя — Telegram API нужен настоящий чат.
4. **Проценты комиссии** — сейчас 2% по умолчанию (`commission_subscription_bp`), меняется в админке.

## Открытые вопросы

1. **Льготный период.** Сейчас по истечении срока доступ отзывается сразу. Нужен ли день-два отсрочки?
2. **Возврат при ручном отзыве.** Механика отзыва есть, автоматического возврата денег нет — возврат делается вручную.
3. **Реферальные с подписок.** Настройка `referral_applies_to` содержит `subscription`, но само начисление сейчас срабатывает только на обычные товары. Подключается на этапе 6 вместе со вторым уровнем рефералов.
