# Общая приёмка этапов 1–3

Статус: **автоматическая часть выполнена 01.11.2026** — [результаты](PROJECT-AUDIT-2026-11-01.md). **Этап 3 выложен** по отдельному запросу пользователя — [выкладка и ручной чеклист](DEPLOY-STAGE-3-2026-11-01.md), production a0032giveaways. Настоящий Telegram Desktop и production-админка проверены после выкладки; телефонные особенности и mainnet остаются для ручной приёмки. Подробный сокращённый список — в отчёте выкладки. Автоматические проверки ниже выполнены на изолированной копии; не повторять их на рабочей БД. Инфраструктура — [acceptance/README.md](../acceptance/README.md).

## Стенд и фиксация результата

- Зафиксировать SHA/манифест кандидата, версии сборок, Alembic head и безопасный URL тестовой БД. Подготовить отдельные admin/moderator/buyer/seller.
- БД — отдельная восстановленная копия. До pytest проверить TEST_DATABASE_URL: fixture удаляет public schema. Рабочую БД не использовать.
- Перехватить весь Telegram Bot API: заданные getMe/getChatMember/send* ответы, журнал без токенов, 403/429/timeout. Обычного перехвата sendMessage недостаточно для новых membership/preflight вызовов.
- Не запускать рабочий polling-бот и не использовать реальный кошелёк в автоматическом тесте. Для TON API задать контролируемые on-chain ответы.
- Таблица результатов или акт: сценарий, expected/actual, окружение, дата, доказательство, остаток. Сохранять только обезличенные данные.

## Этап 1

- Telegram initData: корректный вход, изменённая подпись, устаревшее время; закрытый dev-auth.
- Admin/moderator: вход, лимит попыток, refresh/revoke/logout-all, смена пароля, прямые запрещённые маршруты. Модератор не видит настройки этапа 3.
- Обязательная категория, условия RU/EN и новая версия согласия; окно отзывов 30 дней, скрытые отзывы, публикация проверенного продавца, повторные уведомления проверки.
- Удаление фото, кабинет подписок, escrow/dispute/refund/release и финансовый ledger; повтор запросов не создаёт второе списание.
- Backup → восстановление в отдельную БД, systemd timers/мониторинг, приватные логи. Сохраняются открытые пункты прошлой приёмки: пароль владельца, реальные уведомления/телефон, внешнее хранение бэкапов. Отдельный тестовый бот отложен пользователем.

## Этап 2

- Родительская категория → подкатегория → выдача без потери фильтра; все сортировки и пагинация.
- Поделиться товаром → Telegram startapp deep link → нужный товар; снятый/удалённый товар.
- Лента продаж показывает только завершённые продажи; escrow/отмена/возврат/платёж продвижения в неё не попадают.
- Продвижение за 0,3 Gram/24 ч через TON Connect: точная сумма, адрес, сеть, comment/срок; недостаточная/поздняя/чужая оплата, повторное подтверждение, подтверждение после перезапуска и истечение приоритета.
- Кабинет каналов и существующие витрины/подписки, RU/EN, темы и телефонная ширина.

## Этап 3

- Выбрать участников, открыть рейтинг; 70/30 на известной выборке, реальные/fake/hidden отзывы, ноль продаж/ничья. Недельная граница MSK, простой через несколько недель, неизменность архива, два scheduler runner.
- Изменить участие на следующую неделю и видимость сразу; места 1–3/рамки, hidden/blocked, обычная оценка магазина. Публичный API не раскрывает оборот/score, модератор получает 403.
- Крупная RELEASED-сделка → одна запись outbox после commit. Rollback → нет записи; сбой Telegram не отменяет финансовую операцию.
- Порог/чат/тема, права бота, безопасное фото/его отсутствие/удалённый товар. Отключение и смена получателя не перенаправляют старые задания. 429, 403, timeout и падение после send; unknown не отправляется снова до ручной сверки.
- Розыгрыш: draft → preflight → publish; запрещённое редактирование, даты/повтор чатов, отмена, ручная выдача только после winner.
- Join: идентичность backend, все статусы getChatMember, cooldown/concurrent join, потеря прав бота/429/timeout, blocked user, deadline во время сети. Ошибка API не допускает участника автоматически.
- Draw: 0/1/N заявок, отписавшийся кандидат, потеря связи и повтор того же кандидата, crash/два runner/рестарт, один неизменяемый winner, история попыток. Проверить публичную приватность ID и собственную заявку после перезагрузки.

## Сквозные проверки

- Категория/deep link → покупка → escrow/спор/выдача → отзыв → рейтинг; крупная сделка создаёт пост только по настроенному правилу.
- Через nginx проверить публичный кеш и отсутствие персонального кеша; загрузку новых сборок, API, health, revision check. Нагрузку выполнить с перехваченным Telegram и измерять p95/ошибки относительно этапа 2, не подставляя старые числа.
- Браузерный smoke с подменённым API доступен отдельно: `node acceptance/stage3-ui-smoke.cjs` из корня, после установки зависимостей frontend/admin и доступности Playwright/Chromium. `PLAYWRIGHT_MODULE` задаёт путь к модулю, `BROWSER_CHANNEL=msedge` выбирает Edge. Этот smoke не заменяет HTTP/nginx и реальный Telegram.
- Разрешённые реальные сценарии оформить отдельно: бот/чат/тема/пост, подарок/участники/ручная выдача, сумма и кошелёк mainnet. До этого внешний outbox выключен, реального розыгрыша и затрат нет.
